# Разработка, выпуск и диагностика

## Окружение

- Windows (проекты `net8.0-windows` и установщик собираются только на ней), .NET SDK 8+, Inno Setup 6 с ISPP (`choco install innosetup`), Windows PowerShell 5.1.
- Решение `FleetManager-agent.sln`; тесты — `tests/FleetManager.Agent.Core.Tests` (xUnit, ссылается на Core).

```powershell
dotnet build FleetManager-agent.sln -c Release
dotnet test tests/FleetManager.Agent.Core.Tests/FleetManager.Agent.Core.Tests.csproj
powershell -NoProfile -ExecutionPolicy Bypass -File tests/install_script.tests.ps1
.\build-installer.ps1 -AppVersion 0.0.0.1
```

Первые два тестовых прогона обязательны перед пушем. Сейчас в наборе 249 тестов xUnit (`AgentConfiguration`, `AgentPipe`, `AgentSelfUpdate`, `AgentStatusPresenter`, `AgentVersion`, `DataFolderSecurity`, `DomainControllers`, `HardwareComponents`, `LicenseActivation`, `PinRoute`, `RegistrationTiming`, `ServerRoute`, `SshHealth`, `SshService`, `Wallpaper`, `WindowsInventory`).

`tests/install_script.tests.ps1` — не Pester, а скрипт статических проверок: он регулярными выражениями читает `FleetManagerAgent.iss`, `uninstall.ps1`, `AgentWorker.cs` и `FleetManagerApiClient.cs` и падает, если нарушены договорённости (нет `install.ps1`, установщик не требует токен при первой установке, переносит регистрацию при обновлении, читает `agent.json` без учёта регистра, ограничивает SSH адресом сервера и т. д.). При успехе печатает `INSTALL_SCRIPT_TESTS_OK`. Проверки компиляции Pascal-кода `.iss` нет — её даёт только сборка `build-installer.ps1` (в CI — `pr-check`).

## Ветки и выпуск

- `main` защищена: прямой пуш запрещён, в том числе администратору (`enforce_admins`), force-push и удаление ветки заблокированы, нужен Pull Request (одобрений не требуется).
- Рабочий цикл на практике: ветка `feature/…` или `fix/…` **от актуального `main`** → PR в `main` → слияние обычным merge-коммитом (`Merge pull request #N …`). Ветка `develop` в репозитории есть, но отстаёт от `main` (39 коммитов на 2026-10-29) и не используется; не отталкивайтесь от неё.
- `.github/workflows/pr-check.yml` на каждый PR в `main` (`windows-latest`): `dotnet test`, `tests/install_script.tests.ps1`, полная сборка `build-installer.ps1 -AppVersion 0.0.0.<run>` (компилирует Pascal-код `.iss`). Ничего не публикует.
- `.github/workflows/build-installer.yml` при пуше в `main`, если затронуты `src/**`, `installer/**` или `build-installer.ps1`, собирает установщик и публикует GitHub Release с `FleetManagerAgent-Setup.exe`. Версия и тег — `<UTC-дата yyyy.MM.dd>.<номер запуска>`, например `v2026.10.28.28`; дату берёт **UTC**, поэтому слияние в 01:40 по местному времени (+05) получает вчерашнюю дату. Пороговые версии на сервере (`SELF_UPDATE_SINCE` и подобные) сверяйте с `gh release list`, а не с календарём.
- Изменения, не затрагивающие эти пути (документация, `README`, `docs/`, сами файлы workflow), сборку **не запускают**: релиз не создаётся. Markdown в `installer/` (справочник `USAGE.md`) исключён из фильтра правилом `!installer/*.md`, чтобы правка текста не выпускала новую версию. Любая другая правка в `installer/**`, в том числе комментария в `.iss`, релиз выпускает.
- Релизы создаются только через CI. Ручной `workflow_dispatch` публикует настоящий публичный Release — запускать только по явной просьбе владельца.
- Не коммитить `bin/`, `obj/`, `publish/`, `dist/`, `.vs/`, `TestResults/` (они в `.gitignore`).

### От релиза до ПК

1. Слияние в `main` → CI публикует Release.
2. Сервер раз в час (Celery beat, `sync-agent-installer`) и по кнопке «Проверить обновление агента» подтягивает свежий установщик из GitHub Releases в `soft_share_dir`; SHA-256 пересчитывается при смене файла. Копия на точку раздачи (rsync на `10.152.240.10:8088`) обновляется после загрузки и каждые 15 минут. Тег релиза становится «доступной версией».
3. Администратор запускает «Обновить агент» на выбранных хостах (по SSH, первый ПК — canary) — либо ПК без SSH получают предложение в ответе на heartbeat и обновляются сами.
4. Версия, которую ПК присылает в heartbeat, подтверждает результат.

На 2026-10-29 доступная версия — `2026.10.28.28`; из 1 335 ПК с агентом 1 000 уже на ней, остальные — на 2026.10.25.25 (256), 2026.10.24.24 (32) и более старых.

## Диагностика на ПК

Все пути — под `C:\ProgramData\FleetManagerAgent` (читать можно только администратору).

| Что проверить | Как |
|---|---|
| Служба работает | `Get-Service FleetManagerAgent` (запуск — панель управления или `sc.exe start FleetManagerAgent`) |
| Журнал службы | `Get-Content logs\agent.log -Tail 100` или вкладка «Журнал» панели |
| Журнал установки | `logs\install.log`; самообновления — `updates\install-<версия>.log` |
| Состояние глазами сервера | трей: наведение — подсказка; панель управления — карточка состояния |
| Версия агента | панель управления, «Версия агента»; запись «FleetManager Agent» в «Программах и компонентах» |
| sshd | `Get-Service sshd`, `Get-NetFirewallRule -Name FleetManager-Agent-SSH`, `Select-String 'FleetManager SSH source' C:\ProgramData\ssh\sshd_config` |
| Ключ сервера | `C:\ProgramData\ssh\administrators_authorized_keys` (права: только SYSTEM и Администраторы) |
| Маршруты мимо VPN | `route print -4` (маршруты `/32` до сервера, точки раздачи и контроллеров домена) |

Что видит сервер, смотрите в карточке хоста (раздел «SSH», вкладка «Оборудование»).

### Состояния в трее и панели

| Заголовок | Причина (`AgentIssue`) | Подсказка пользователю |
|---|---|---|
| Служба агента не отвечает | служба не запущена или канал недоступен | Проверьте, что служба FleetManagerAgent запущена |
| Служба запускается / останавливается | `Starting` / `Stopping` | — |
| Синхронизация… | идёт синхронизация | время прошлой синхронизации |
| Адрес сервера не задан | `ServerNotConfigured` | Укажите его в панели управления |
| Агент не зарегистрирован | `NotEnrolled` | Нет токена регистрации: переустановите агент с `/EnrollmentToken` |
| Ожидает перезагрузки | `AwaitingReboot` | Агент зарегистрируется после перезагрузки под новым именем ПК |
| Нет связи с сервером | `ServerUnreachable` | время прошлой успешной синхронизации |
| Сервер отклонил запрос | `ServerRejected` | то же |
| Ошибка синхронизации | `Failed` или `Degraded` без известной причины | то же; полный текст — в панели |
| Ожидание первой синхронизации | синхронизаций ещё не было | — |
| Подключено к серверу | всё в порядке | когда синхронизировано и когда следующая |

## Типичные случаи

| Симптом | Причина | Что делать |
|---|---|---|
| ПК не появляется на сервере, в трее «Нет связи с сервером» | Нет связи (DNS, сеть, таймаут) или VPN забрал маршрут к серверу | `agent.log`; проверить `ServerUrl` в панели; на ПК с VPN — `PinServerRoute` и доверенный шлюз ([ssh-and-connectivity.md](ssh-and-connectivity.md#маршруты-мимо-vpn)) |
| «Сервер отклонил запрос» | Сервер ответил HTTP-ошибкой при регистрации или heartbeat: токен регистрации истёк (`401`), дубль `machine-id` (`409`) | Выпустить новый токен; при `409` удалить `machine-id` и перезапустить службу |
| «Ожидает перезагрузки» | Имя ПК сменилось, но перезагрузки ещё не было (AutoDomain) | Перезагрузить; регистрация произойдёт под новым именем |
| ПК присылает heartbeat, но Ansible не заходит | sshd остановлен/отключён, нет правила брандмауэра, GPO игнорирует локальные правила, PATH без System32, оболочка не PowerShell | Раздел «SSH» в карточке хоста; агент сам чинит всё, кроме GPO и отключённого sshd |
| `domain_trust: unreachable` | Нет контроллера домена (ПК вне сети или VPN забрал маршрут) | Подключить ПК к сети; агент закрепляет маршрут до контроллеров, если шлюз доверенный |
| `domain_trust: broken` | Нарушено доверие с доменом (часто — второй ПК с тем же именем) | Ввести ПК в домен заново; сервер ждёт запасной вход под локальным администратором (в разработке) |
| Служба не стартует после установки, события 7000/7009 | Smart App Control в режиме оценки (SU5-F*): первый запуск не укладывается в 30 с | Ничего: установщик повторяет запуск, а задача `FleetManager-Agent-start-retry` стартует службу через 5 и 10 минут после загрузки |
| `OpenSSH Server не установлен (0x800f0954)` | WSUS не отдаёт компонент Features on Demand | Сервер предложит ремонт; установщик поставит sshd из вшитого MSI |
| Обновление агента висит | Установщик держит потоки SSH-сессии (раньше — запущенный им трей) | Ничего: трей стартует из планировщика; если повторилось — `install.log` и `updates\install-*.log` |
| Обои не меняются | Групповая политика домена перекрывает локальную, либо ПК без трея в сеансе | `wallpaper-state.json`, поле `error` отчёта `wallpaper` в карточке хоста; экран блокировки меняется при следующей блокировке |
| Хост показывает «Версия устарела», а самообновление не идёт | Агент старше `2026.10.24.24`, или уже было 3 попытки на эту версию, или нет SHA-256/установщика на сервере | `self-update.json`, `agent.log` («Server offers agent …»); для старых агентов — установка на месте |

## Памятка разработчику

- **Pipe-протокол — одна строка на сообщение.** Никогда не включайте `WriteIndented` в `JsonDefaults.Options` и в `JsonWireOptions` канала: многострочный JSON обрезается до `{`.
- **`agent.json` читается без учёта регистра** — и в C#, и в Pascal-коде установщика (`JsonString`/`JsonInteger`); новое поле добавляйте в `AgentOptions`, иначе служба затрёт его при перезаписи файла (так было с `SshSourceAddress`).
- **Подсказка `NotifyIcon.Text` — до 127 символов**, иначе исключение: используйте `AgentStatusPresenter.Tooltip`.
- **Тексты состояния** — только из `AgentStatusPresenter`, не дублируйте в Tray и Control.
- **Установщик:** многопараметровый вызов командлета в генерируемом PowerShell пишите в **одной строке** — перевод строки через `NL` обрывает команду; не используйте в Pascal символьные литералы `#13/#10` (ISPP воспринимает их как директивы) — есть `NL`; все значения в PowerShell оборачивайте `PsLiteral`; каждый шаг логируйте в `install.log` и по возможности делайте нефатальным.
- **Новые поля в heartbeat** добавляйте только необязательными и обновляйте [server-protocol.md](server-protocol.md); сервер должен переживать их отсутствие, а агент — их игнорирование.
- **Записывайте файлы инструментами редактора, а не heredoc-ами Bash:** в Git Bash heredoc съедает обратные слэши (`\n`, `\\` в C#-литералах и регулярках).
- Никогда не запрашивайте у `Win32_Product`: это запускает самовосстановление каждого MSI на ПК.
