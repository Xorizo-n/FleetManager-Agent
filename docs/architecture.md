# Архитектура агента

Агент Fleet Manager — набор из трёх процессов Windows и общих библиотек. Служба работает от `LocalSystem` и делает всю работу; трей и панель управления — только интерфейс к ней. Все проекты — .NET 8 (`net8.0` / `net8.0-windows`), собираются self-contained под `win-x64`.

```
                         ┌────────────────────────────────────────────────────────┐
                         │  FleetManagerAgent (служба, LocalSystem)               │
 Fleet Manager           │  AgentWorker → синхронизация каждые SyncIntervalMinutes│
 (сервер, :8080) ◄───────┤  ├ регистрация / heartbeat / alerts / offline          │
   HTTP + Bearer         │  ├ инвентаризация (PowerShell, WMI, реестр)            │
                         │  ├ SshService + SshHealthChecker (sshd, брандмауэр…)   │
                         │  ├ ServerRouteKeeper (маршруты мимо VPN)               │
                         │  ├ WallpaperManager (локальная групповая политика)     │
                         │  ├ AgentSelfUpdate (обновление без SSH)                │
                         │  └ AgentPipeServer  ◄── Named Pipe «FleetManagerAgent» │
                         └───────────────────────────▲────────────────────────────┘
                                                     │ status / logs / sync / set-server-url
                         ┌───────────────────────────┴───────────┐
                         │ Tray (пользователь, без UAC)          │
                         │   └─ runas ─► Control (администратор) │
                         └───────────────────────────────────────┘
```

## Проекты

| Проект | Тип | Назначение |
|---|---|---|
| `FleetManager.Agent.Core` | библиотека `net8.0` | Вся логика агента: конфигурация, `machine-id`, состояние, журнал, Named Pipe, API-клиент, инвентаризация, SSH, маршруты, обои, активация, самообновление, защита папки данных. Общая для остальных проектов и для тестов. |
| `FleetManager.Agent.Service` | `net8.0`, Windows-служба | `AgentWorker` (цикл синхронизации), `ServerRouteKeeper` (маршруты мимо VPN). Зависимость — `Microsoft.Extensions.Hosting.WindowsServices`. |
| `FleetManager.Agent.Ui` | библиотека `net8.0-windows` | Общий WinForms-слой в стиле Windows 11: тема (светлая, тёмная, высокий контраст, акцентный цвет системы), шрифты Segoe UI Variable, Fluent-иконки, карточки, кнопки, поле ввода, меню, иконка трея с индикатором проблем. |
| `FleetManager.Agent.Tray` | `WinExe` | Иконка в области уведомлений, по одной на сеанс (мьютекс `Local\FleetManagerAgent.Tray`). |
| `FleetManager.Agent.Control` | `WinExe`, manifest `requireAdministrator` | Панель управления (мьютекс `Local\FleetManagerAgent.Control`). |

В `publish\win-x64` все три исполняемых файла лежат вместе, поэтому `FleetManager.Agent.Ui.dll` и среда выполнения общие — установщик забирает их маской `publish\win-x64\*`.

## Цикл синхронизации

`AgentWorker.ExecuteAsync` выполняет синхронизацию сразу после старта, затем через `SyncSchedule.NextDelay`:

- обычно — `SyncIntervalMinutes` из `agent.json` (по умолчанию 5, границы 1…1440);
- пока агент ещё не зарегистрирован (есть `EnrollmentToken`, нет `AgentToken`) — раз в минуту: сразу после загрузки сеть часто ещё не поднята, и свежий ПК не должен ждать целый интервал.

Синхронизацию можно запустить вручную из трея или панели управления (команда `sync` по каналу). Параллельные запуски сериализует `SemaphoreSlim`, поэтому периодический цикл и ручной запуск не пересекаются.

Один проход `SyncOnceAsync`:

1. Перечитать `agent.json` (его могла изменить панель управления или установщик).
2. Если задан адрес сервера — `ServerRouteKeeper.EnsureAsync`: закрепить маршрут до сервера, точки раздачи и контроллеров домена мимо VPN (подробнее — [ssh-and-connectivity.md](ssh-and-connectivity.md)).
3. **Регистрация** (`EnsureRegistrationAsync`), если нет `AgentToken`:
   - нет и `EnrollmentToken` → ошибка `NotEnrolled`;
   - ожидается переименование ПК (`ComputerRename.IsPending`) → состояние `AwaitingReboot`, проход заканчивается, ничего не отправляется;
   - иначе `POST /api/agent/register`. Ответ (`agent_id`, `agent_token`, `ssh_public_key`, `ssh_login`) записывается в `agent.json`, `EnrollmentToken` стирается, публичный ключ ставится в `administrators_authorized_keys`.
4. **SSH**: `SshService.Ensure` (состояние и автозапуск sshd), затем `SshHealthChecker.CheckAsync` (брандмауэр, `sshd_config`, PATH, оболочка, права входа, доверие с доменом, ключи хоста). Сбой проверки только пишется в журнал и heartbeat не срывает.
5. **Инвентаризация**: железо (`CollectHardwareAsync`), ПО (`CollectSoftwareAsync`), активация (`CollectActivationAsync`, не чаще раза в час).
6. Если есть сервер: повторно установить SSH-ключ (на случай, если файл переписали), собрать состояние обоев, отправить **heartbeat** и обработать ответ:
   - `pin_routes` → маршруты до точки раздачи;
   - `wallpaper` → применить назначенные обои;
   - `agent_update` → самообновление без SSH (не чаще раза в час, не больше трёх попыток на версию);
   - после успешного heartbeat `ConfirmPathAsync` запоминает шлюз, через который сервер реально ответил.
7. Если отпечаток железа изменился с прошлой синхронизации — `POST /api/agent/alerts` (`hardware_changed`).
8. Обновить `AgentState` (время синхронизации, число программ, отпечаток).

Любое исключение переводит агент в состояние `Degraded`, записывает ошибку в журнал и в `AgentStatus.LastError`; причина классифицируется `AgentIssues.Classify` (`ServerUnreachable` — сеть, DNS, таймаут; `ServerRejected` — сервер ответил HTTP-ошибкой; `NotEnrolled`, `ServerNotConfigured`, `AwaitingReboot`, `Failed`).

При остановке службы отправляется `POST /api/agent/offline`, чтобы сервер сразу пометил ПК выключенным.

## Что собирается

Все скрипты выполняются через `powershell.exe` с UTF-8 на выходе (русская Windows иначе отдаёт cp866).

| Данные | Источник | Частота | В отпечатке железа |
|---|---|---|---|
| Производитель, модель | `Win32_ComputerSystem` | каждый проход | да |
| Серийный номер | `Win32_BIOS` | каждый проход | да |
| Название ОС | реестр (`ProductName`, `CurrentBuildNumber`), приведено к «Microsoft Windows 11 …» независимо от языка интерфейса | каждый проход | да |
| Процессор, объём ОЗУ | `Win32_Processor`, `Win32_ComputerSystem` | каждый проход | да |
| Сетевые адаптеры (MAC, IPv4/префикс, статус, тип среды, скорость линка) | `Get-NetAdapter -Physical`, `Get-NetIPAddress`; Bluetooth и адаптеры без MAC отброшены | каждый проход | нет (док-станции и USB-адаптеры давали бы ложные алерты) |
| Локальные несъёмные диски (корень, метка, ФС, размер, свободно) | `DriveInfo` | каждый проход | нет |
| Состав рабочего места: плата, BIOS, модули памяти, физические диски, видеокарты, мониторы (EDID), клавиатуры и мыши, прочие USB | `HardwareComponentsCollector` (WMI, PnP) | каждый проход | нет |
| ПО | ключи Uninstall (HKLM, Wow6432Node, HKCU — значения читаются по одному, битая запись не роняет весь список), `Get-AppxPackage -AllUsers`, Chocolatey, winget | каждый проход | нет |
| Активация Windows и Office | `SoftwareLicensingProduct`, журнал KMS-клиента, проба TCP-порта KMS, CMID | раз в час (`LicenseActivationCollector.RefreshInterval`) | нет |
| Обои | реестр, `Registry.pol`, PersonalizationCSP | каждый проход | нет |
| Состояние SSH | `SshService`, `SshHealthChecker` | каждый проход; проверки входа и домена — раз в час | нет |

**Отпечаток железа** — первые 16 символов SHA-256 от `производитель|модель|серийный|ОС|процессор|память`. Агент сравнивает его с предыдущим проходом и при расхождении отправляет алерт. Сервер сам определяет смену железа по полям и содержимое алерта `hardware_changed` не сохраняет (только два хэша), поэтому алерт — совместимость со старыми версиями сервера.

Состав рабочего места намеренно вне отпечатка: периферию переподключают постоянно. Журнал изменений и алерты об исчезновении клавиатуры, мыши или монитора ведёт сервер.

## Папка данных `%ProgramData%\FleetManagerAgent`

| Файл или папка | Что это | Кто пишет |
|---|---|---|
| `agent.json` | Настройки и регистрация (см. ниже). Содержит токен агента. | установщик, служба, панель управления |
| `machine-id` | GUID ПК для сервера. Создаётся при первом запуске. | служба |
| `logs\agent.log` | Журнал службы: `ISO-время [INFO\|WARN\|ERROR] сообщение`. | служба |
| `logs\install.log` | Журнал шагов установки (`Log` в сгенерированном PowerShell). Из него служба берёт `install_error`, если sshd не поставился. | установщик |
| `server-route.json` | Доверенные шлюзы (до 16) и адреса точки раздачи, чтобы маршруты вернулись после перезагрузки до первого heartbeat. | `ServerRouteKeeper` |
| `self-update.json` | Версия, число попыток и время последней попытки самообновления. | `AgentSelfUpdate` |
| `updates\` | Скачанный установщик `FleetManagerAgent-Setup-<версия>.exe` и его `install-<версия>.log`. Перед каждой попыткой очищается. | `AgentSelfUpdate` |
| `wallpaper-state.json` | Что агент поставил и исходные значения образа для отката. | `WallpaperManager` |
| `wallpapers\` | Скачанные картинки каталога. Единственная подпапка, доступная на чтение «Пользователям». | `WallpaperManager` |

Права на папку: полный доступ только у SYSTEM и Администраторов, наследование от `ProgramData` отключено, владелец — Администраторы; «Пользователи» читают только `wallpapers\`. Права выставляет установщик (`RestrictDataFolder`, `icacls` по SID), а служба проверяет их при каждом старте (`DataFolderSecurity.Repair`) и удаляет ссылки (junction, symlink) внутри папки — иначе SYSTEM писал бы и удалял файлы там, куда указал подложивший ссылку. Неэлевированные процессы файлов отсюда не читают: трей получает состояние только по каналу.

### `agent.json`

Установщик пишет файл в PascalCase, служба перезаписывает в camelCase; чтение везде регистронезависимое (и в C#, и в Pascal-коде установщика).

| Поле | По умолчанию | Назначение |
|---|---|---|
| `ServerUrl` | — | Адрес сервера (`http://` или `https://`, без завершающего `/`). Меняется в панели управления. |
| `EnrollmentToken` | — | Одноразовый токен регистрации. После регистрации стирается. |
| `AgentId`, `AgentToken` | — | Идентификатор и токен агента, выданные сервером. |
| `SshPublicKey` | — | Публичный ключ сервера для входа по SSH. |
| `SshLogin` | текущий пользователь | Учётная запись, под которой сервер входит по SSH (`ДОМЕН\пользователь`). Уходит в каждом heartbeat. |
| `SshSourceAddress` | адрес хоста из `ServerUrl` | С каких адресов разрешён SSH (IPv4/CIDR через запятую). Хранится в файле, чтобы переустановка не потеряла значение. |
| `SyncIntervalMinutes` | `5` | Период синхронизации, 1…1440 минут. |
| `PinServerRoute` | `true` | `false` — не трогать маршруты (сервер, точка раздачи, контроллеры домена). |
| `KeepSshRunning` | `true` | `false` — sshd и его окружение только проверяются и сообщаются, ничего не чинится. |

## Named Pipe

Канал `\\.\pipe\FleetManagerAgent`, строки JSON по одной на сообщение (`WriteLineAsync`/`ReadLineAsync`). Поэтому сериализация **никогда** не должна быть с отступами: переносы строк обрезали бы сообщение до `{`. Параметры вынесены отдельно (`JsonWireOptions`), чтобы глобальные настройки их не сломали.

Канал обслуживает до 8 клиентов одновременно: команда `sync` держит соединение до конца синхронизации, и с единственным экземпляром трей в это время не мог бы получить статус (`AgentPipeTests`). Права на канал: SYSTEM и Администраторы — полный доступ, прошедшие проверку пользователи — чтение и запись, иначе неэлевированный трей не смог бы подключиться к службе.

| Команда | Параметр | Кто может | Ответ |
|---|---|---|---|
| `status` | — | любой пользователь | `AgentStatus` |
| `logs` | число строк (по умолчанию 200) | любой пользователь | последние строки `agent.log` |
| `sync` | — | любой пользователь | `AgentStatus` после синхронизации |
| `set-server-url` | новый адрес | только Администраторы (проверка токена клиента через `RunAsClient`) | `AgentOptions` |

`AgentStatus` содержит имя ПК, `machine-id`, состояние (`Starting`/`Running`/`Degraded`/`Stopping`/`Offline`), время запуска, последней синхронизации и следующей, последнюю ошибку и её класс (`Issue`), адрес сервера, число программ, отпечаток железа, версию агента, признак идущей синхронизации и ревизию обоев (`WallpaperRevision`).

## Интерфейс

Тексты состояния («Подключено к серверу», «Нет связи с сервером» и т. д.) формирует единственный источник — `AgentStatusPresenter`; его используют и трей, и панель управления. Подсказку `NotifyIcon.Text` (лимит 127 символов, иначе исключение) строят только через `AgentStatusPresenter.Tooltip`.

**Трей.** Запускается автоматически через `HKLM\Software\Microsoft\Windows\CurrentVersion\Run` (`FleetManagerAgentTray`). Опрашивает службу каждые 15 секунд и при наведении (не чаще раза в 5 секунд). Меню: «Синхронизировать сейчас», «Открыть панель управления», «Скрыть значок» (служба продолжает работать, значок вернётся при следующем входе). Иконка показывает индикатор проблем. Открытый рабочий стол трей обновляет сам, когда меняется `WallpaperRevision`: служба работает от SYSTEM и меняет политику, а рабочий стол перечитывает её только при входе.

**Панель управления.** Открывается из трея через `runas` (UAC). Если панель уже открыта — выводится на передний план без повторного запроса. Показывает состояние, адрес сервера (поле с проверкой и кнопкой «Сохранить»), сведения о ПК (имя, версия агента, число программ, время запуска службы, идентификатор), журнал службы (цветные уровни, «Обновить», «Открыть папку»). Обновляется каждые 5 секунд. Если служба не отвечает, главная кнопка превращается в «Запустить службу» (`sc.exe start`) — панель работает от администратора.

## Версия агента

`AgentVersion.Current` берёт `AssemblyInformationalVersion` (строка как есть, например `2026.10.05.5`; `AssemblyVersion` уже нормализован до `2026.10.5.5`), метаданные сборки после `+` отбрасываются. Номер проставляет `build-installer.ps1`: он же уходит в `/DAppVersion` установщика, и версия из heartbeat совпадает с `DisplayVersion` записи удаления Windows, которую сервер читает при проверке по SSH. Сравнение версий — числовое по компонентам (`AgentSelfUpdate.Compare`).
